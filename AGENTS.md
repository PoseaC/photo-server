# AGENTS.md

Guidance for AI agents and developers working in this repository. Read this
before making changes.

## What this project is

A **single-page static frontend** for a wedding photo/video upload page
("Alexandra & Iustin – 5 Iulie 2026"). Guests open the site, pick photos/videos,
and the browser uploads them **directly to a self-hosted Immich album** via an
Immich **public shared link**. There is **no application backend** in this repo —
the only server-side piece is the nginx that serves the static bundle and proxies
`/api` to Immich (see Docker section).

UI text is in **Romanian**. The app is **mobile-first**.

## Tech stack

- **React 17** + **TypeScript** (class components; React is loaded as UMD globals
  from `bin/vendor/`, not bundled — see `webpack.config.js` CopyPlugin).
- **Tailwind CSS v4** via `@tailwindcss/cli` (NOT PostCSS). Input
  `src/tailwind-input.css` → output `src/style.css`.
- **Webpack 5** + `ts-loader` bundles `src/index.tsx` → `bin/index.js`.
- No test framework. `npm test` is a placeholder.

## Build & dev commands

The build is **two steps** and Tailwind MUST run before webpack (webpack copies
the generated `style.css` into the output):

```bash
npx @tailwindcss/cli -i ./src/tailwind-input.css -o ./src/style.css
npx webpack --mode=production
```

- **Dev server:** `npm start` (webpack-dev-server, opens browser). Note the dev
  server does NOT run Tailwind — if you change CSS, re-run the Tailwind CLI.
- **Production bundle:** `npm run build` (or the explicit two-step above).
- Output goes to `bin/` (gitignored).

### CRITICAL Tailwind gotcha

Tailwind only emits class names it **finds in the source at build time**, and
there is **no `--watch`** wired up. If you add a NEW utility class (e.g.
`md:mb-0`) that isn't already used elsewhere, you MUST re-run the Tailwind CLI or
it won't exist in `style.css` and will silently do nothing. Classes already
present in `style.css` work without a rebuild.

## Project structure

```

  mainMenu.tsx       # Main screen: select/clear/gallery buttons, starts upload

  success.tsx        # "Mulțumim" screen + gallery button
  immich.ts          # All Immich API logic (share key, upload, validation)
  env.d.ts           # Ambient declarations for __IMMICH_*__ build-time globals
  index.html         # HTML shell (viewport meta, vendor scripts)

  style.css          # GENERATED by Tailwind CLI (committed)
  img/               # SVG icons + hero photo

  Dockerfile         # Multi-stage build (node builder -> nginx runtime)
  docker-compose.yml # Service def (image, build args, IMMICH_UPSTREAM, port 8082)
  default.conf.template  # nginx config: serves app + proxies /api -> Immich
```

### App state machine

`Index` (in `index.tsx`) holds all shared state and renders one of three screens
by `activeMenu`: `main` | `loading` | `success`. State is **hoisted into `Index`**
(selected files, upload progress, abort controller) because each screen unmounts
on transition — do NOT store upload state on a child component or it is lost.
`setActiveMenu()` runs a fade-out/fade-in animation between screens.

## Immich integration (the important part)

- Shared link: `https://immich.adasiiustin.me/s/adasiiustin`
  → slug = `adasiiustin`. The share is **public (no password)** with **uploads
  enabled** (`allowUpload`).
- **Two API calls** (`src/immich.ts`):
  1. `GET /api/shared-links/me?slug=<slug>` → returns the share's **`key`**
     (base64url). The KEY, not the slug, authorizes uploads. Cached after first call.
  2. `POST /api/assets?key=<key>` (multipart/form-data) per file. Required form
     fields: `assetData` (File), `deviceAssetId`, `deviceId`, `fileCreatedAt`,
     `fileModifiedAt`, `isFavorite`.
- **Status codes:** `201` = created, `200` = duplicate (Immich dedupes by
  checksum). BOTH are success — re-uploading the same file is safe/idempotent.
- **Uploads use `XMLHttpRequest`**, not `fetch`, specifically to get
  `upload.onprogress` byte events for the percentage UI (fetch can't report
  request-body progress).
- **Concurrency:** `UPLOAD_CONCURRENCY = 3` (worker pool in `uploadFiles`). Mirrors
  Immich's own web uploader. Keep low so many simultaneous guests don't melt the Pi.
- **Retry:** up to 4 attempts with exponential backoff + jitter, only on network
  errors / 429 / 5xx. Honors the `AbortSignal`.
- **Validation:** `isSupportedFile()` checks the file EXTENSION against Immich's
  supported image/video sets (MIME is unreliable on mobile). Unsupported files are
  skipped with a Romanian alert.
- The file `<input>` uses `accept="image/*,video/*"` (NOT the long extension list)
  so mobile opens the photo gallery directly instead of a document/Drive picker.
  iOS still shows a small action sheet — that is unavoidable for a web file input.

## Configuration (build-time, NOT runtime for the bundle)

Immich config is **baked into the JS at build time** via webpack `DefinePlugin`:

- `__IMMICH_BASE_URL__`  ← `process.env.IMMICH_BASE_URL`  (e.g. https://immich.adasiiustin.me)
- `__IMMICH_SHARE_SLUG__` ← `process.env.IMMICH_SHARE_SLUG` (e.g. adasiiustin)
- `__IMMICH_API_BASE__`  ← `""` always now (relative `/api`), so the browser calls
  the SAME origin and there is no CORS. The gallery LINK still uses the absolute
  `__IMMICH_BASE_URL__`.

These values are **public** (the share link is public), so they are NOT secrets and
are safe to pass as Docker build args. The real config lives in `.env` (gitignored).

To change the Immich URL/slug you must **rebuild** the bundle/image — there is no
runtime swap for these in the static bundle.

## CORS / same-origin design

The browser must never make a cross-origin call to Immich, because Immich (behind
Nginx Proxy Manager) does NOT send `Access-Control-Allow-Origin`. Two mechanisms
keep requests same-origin:

- **Development (`npm start`):** webpack-dev-server `devServer.proxy` forwards
  `/api` → `IMMICH_BASE_URL` server-to-server (no CORS). It also disables Node's
  300s `requestTimeout` and raises proxy timeouts so large uploads aren't cut off.
  This is DEV-ONLY (gated on `process.env.WEBPACK_SERVE`).
- **Production (container):** the container's own nginx proxies `location /api/`
  → `${IMMICH_UPSTREAM}` (see `docker/default.conf.template`). So the app and the
  API are the same origin. `IMMICH_UPSTREAM` defaults to `http://192.168.0.139:2283`
  (the Pi's LAN address for Immich) and can be changed via the environment WITHOUT
  rebuilding (nginx envsubst at container start).

## Docker / deployment

- **Multi-stage build** (`docker/Dockerfile`):
  - Builder: `node:22-bookworm-slim` (Debian, NOT Alpine — Tailwind v4's native
    `@tailwindcss/oxide`/`lightningcss` need glibc prebuilt arm64 binaries; Alpine
    musl often lacks them and the build fails). Runs `npm ci`, Tailwind, webpack.
  - Runtime: `nginx:alpine` serving `/usr/share/nginx/html`, plus the `/api` proxy
    template. The whole Node toolchain is discarded → small final image.
- **`.dockerignore` MUST be at the repo root** (the build context root). It ignores
  `docker/*` EXCEPT `docker/default.conf.template` (which the Dockerfile copies).
- **Compose** (`docker/docker-compose.yml`): project name `photo-server`, container
  `landing-page-wedding-photo-server`, host port **8082** → container 80,
  `restart: unless-stopped`.

### Target architecture: Raspberry Pi 5 (arm64)

The dev PC is **x86 Windows**; the Pi is **arm64**. A plain `docker build` on the
PC produces an x86 image that WON'T run on the Pi. Cross-build with buildx +
emulation using the `docker-container` driver builder (named `photo-builder`):

```powershell
# One-time builder (if missing):
docker buildx create --name photo-builder --driver docker-container --bootstrap --use

# Build + push arm64 (run from repo root). Tags: latest + a dated rollback tag.
docker buildx build --builder photo-builder --platform linux/arm64 `
  -f docker/Dockerfile `
  --build-arg IMMICH_BASE_URL=https://immich.adasiiustin.me `
  --build-arg IMMICH_SHARE_SLUG=adasiiustin `
  -t ghcr.io/minculeteandrei/photo-server:latest `
  -t ghcr.io/minculeteandrei/photo-server:YYYYMMDD `
  --push .
```

(The emulated arm64 build is slow — several minutes. Docker Desktop must be running;
its launcher on this machine is `D:\Program Files\Docker Desktop\app\Docker Desktop.exe`.)

### Registry: GHCR (private)

- Image: `ghcr.io/minculeteandrei/photo-server` (PRIVATE package).
- GHCR only works with **classic** PATs (fine-grained tokens cannot access
  Packages; Docker Hub's free tier per-repo tokens need a paid OAT). 
- PC (push): classic PAT with `write:packages`. Pi (pull): classic PAT with
  `read:packages` only.

### Deploy on the Pi

```bash
docker compose pull
docker compose up -d
```

Then hard-refresh the site. **No env vars to change on the Pi for routine updates**
— config is baked into the image. The only Pi-side var that matters is
`IMMICH_UPSTREAM` (already set in compose) if Immich's LAN address changes.

## Network topology (context for "why is it slow")

Public domains `galerie.adasiiustin.me` (the app) and `immich.adasiiustin.me` BOTH
resolve to an **Azure VPS (4.233.144.63)** running **Pangolin**, which tunnels to
the home Pi over **WireGuard (Newt connector)**. So remote-guest traffic is:

```
browser → Azure VPS (Pangolin) → WireGuard/Newt tunnel → Pi → app nginx → Immich
```

- PC→VPS measured ~237 Mbit/s; home upload is gigabit — neither is the bottleneck.
- The **Newt userspace-WireGuard tunnel** (CPU-bound) is the throughput cap
  (~20–40 Mbit/s observed). Same-origin/CORS work did NOT change this — it only
  fixed the CORS error. To make remote uploads fast: use kernel WireGuard / tune
  MTU / non-burstable VPS. Guests on the **Pi's LAN** bypass the tunnel entirely
  (gigabit) — best path for the actual event.

### Nginx Proxy Manager (NPM) upload settings

NPM defaults `client_max_body_size` to **1 MB**, which blocks large videos. BOTH
the `immich` and `galerie` proxy hosts in NPM need (Advanced tab):

```nginx
client_max_body_size 0;
proxy_request_buffering off;
proxy_read_timeout 1800s;
proxy_send_timeout 1800s;
```

(`proxy_request_buffering off` streams uploads instead of buffering to disk — also
why the app's own nginx sets it. Without it on the `galerie` host, the app upload
is slower than uploading directly in Immich.)

## Conventions & cautions

- **Romanian UI strings:** in JSX use HTML entities (`&#x103;` etc.) — they render
  correctly in text nodes. In JS string literals (e.g. `alert(...)`) use real
  Unicode escapes (`\u0103`); HTML entities do NOT decode in JS strings.
- **Secrets:** `.env` is gitignored and stays out of the Docker image (in
  `.dockerignore`). Before committing, scan the diff for secrets. The Immich
  URL/slug are public, not secrets.
- **Do NOT** create markdown summary files for each change.
- After UI changes, verify on small mobile viewports (e.g. 360×800 Galaxy S21).
  Browser chrome eats ~120–150px, so design for ~650px visible height. Layout uses
  responsive spacing (small margins/buttons on mobile, full at `md:`), NOT JS
  scaling (a previous fit-to-screen scaling approach was removed — it looked zoomed).
- On upload FAILURE the selection is cleared (state + the file input's `.value`).
  On CANCEL/abort the selection is intentionally KEPT for easy retry (Immich dedupe
  makes re-upload safe).

## Verification workflow used in this repo

- TypeScript: rely on editor diagnostics / `tsc` via `ts-loader` during build.
- Browser testing: Chrome DevTools MCP (navigate, snapshot, evaluate_script,
  emulate viewport, list_network_requests). Upload flow was verified end-to-end
  through the dev proxy (GET shared-links/me → 200, POST assets → 201).
